# Minecraft 26.1.2 Implementation Plan

**Goal:** Preserve Forge 1.20.1 and add working Forge / NeoForge 26.1.2 probes.

**Architecture:** Share version-specific Minecraft code between small loader adapters. Keep legacy code isolated. Validate the HTTP protocol with live probes and plugin installation with Node tests.

**Tech Stack:** Java 25, Gradle 9, ForgeGradle 7, ModDevGradle 2, Node.js.

## Tasks
- [ ] Add plugin regression tests for legacy Forge jars, new Forge/NeoForge jars, mismatched loader/version, and Java home selection; run tests before implementation.
- [ ] Implement loader-aware jar installation and optional Java home on build/prepare/GameTest; update plugin metadata and descriptions.
- [ ] Create the two loader builds and shared 26.1.2 sources; pin NeoForge 26.1.2.114 and Forge 64.1.5.
- [ ] Add an HTTP integration runner specifying expected probe behavior before porting handlers.
- [ ] Migrate Minecraft APIs and lifecycle adapters, compiling against both loaders and resolving compiler failures from actual API signatures.
- [ ] Run real isolated server integration checks, then client status/UI/screenshot checks where available.
- [ ] Review spec compliance and code quality; fix findings and rerun affected checks.
- [ ] Document commands, compatibility matrix and validation results; package artifacts and push to the user's fork.

## Verification commands
- `node --test plugin/minecraft-mod-dev/test/*.test.js`
- `lab/mcdev-probe-neoforge-26.1.2/gradlew.bat build`
- `lab/mcdev-probe-forge-26.1.2/gradlew.bat build`
- `python lab/tools/smoke_probe.py --port 39001`
- `git diff --check`

## Completion criteria
Both new loader artifacts compile, automated checks pass, existing Forge source remains intact, and published documentation clearly distinguishes tested features from any runtime limitations.
